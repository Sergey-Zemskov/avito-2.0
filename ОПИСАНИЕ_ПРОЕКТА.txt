1. ЧТО ИЗМЕНИЛОСЬ ПО СРАВНЕНИЮ С ПРОШЛЫМ ВАРИАНТОМ
================================================================================

Оформление:
  * цвета только чёрный, белый и оттенки серого - никаких цветных кнопок
    и фонов;
  * никаких теней, скруглений, значков и эмодзи, никаких сторонних
    библиотек оформления (Bootstrap и подобных);
  * у сайта есть чёрная шапка с названием и белая строка меню под ней;
  * список объявлений показан таблицей с рамкой, серой строкой заголовков
    и чередованием светлых строк;
  * кнопки - простые прямоугольники с чёрной рамкой; при наведении
    курсора кнопка становится чёрной с белым текстом;
  * у блоков, полей ввода и таблиц есть аккуратные отступы, содержимое
    страницы выровнено по центру и ограничено по ширине.

Функции сайта сокращены до минимума - осталось только то, что
поддерживают пять исходных таблиц базы данных:
  * объявления: список, просмотр, добавление, редактирование, удаление;
  * категории: выпадающий список и фильтр;
  * пользователи: регистрация, вход, выход;
  * избранное: добавить, убрать, посмотреть список;
  * сообщения: написать и прочитать переписку.

Что убрано: счётчик просмотров, статусы объявлений (продано/снято),
панель администратора, SQL-консоль, страницы статистики, диаграммы,
загрузка фото по ссылке, сортировки, постраничный вывод, поля профиля
(имя, телефон, почта), защита форм от CSRF.

Код тоже стал проще: вместо пяти файлов с маршрутами и трёх служебных
модулей теперь один файл app.py, в котором лежат все страницы и все
запросы к базе.

--------------------------------------------------------------------------------
3.1  start.py - ЗАПУСК ОДНОЙ КОМАНДОЙ
--------------------------------------------------------------------------------
НАЗНАЧЕНИЕ
  Этот файл делает всю подготовку, чтобы сайт можно было запустить
  на любой системе буквально одним действием. Его вызывают два
  крошечных файла-обёртки:

      Windows : start.bat   (двойной щелчок)
      Linux   : start.sh    (команда ./start.sh)

  Сами обёртки почти пустые: они только находят Python и передают
  управление в start.py. Так сделано специально: в bat-файл нельзя
  писать русский текст без хлопот с кодировкой, поэтому все сообщения
  выводятся из Python.

ЧТО ДЕЛАЕТ start.py
  1) Проверяет версию Python (нужна 3.6 или новее).
  2) Проверяет, установлены ли библиотеки flask и fdb.
       - если нет, запускает pip install -r requirements.txt;
       - если и это не вышло (например, в Linux запрещена установка
         в системный Python), создаёт отдельную папку .venv, ставит
         библиотеки туда и перезапускает себя уже из неё.
  3) Проверяет, отвечает ли сервер Firebird: пробует соединиться
     с портом 3050.
       - если сервер не отвечает, печатает понятную инструкцию
         (свою для Windows и свою для Linux);
       - на Linux ещё и предлагает установить Firebird командой
         sudo dnf install -y firebird firebird-utils.
  4) Запускает setup_all.py --demo: база данных создаётся, если её
     нет, структура обновляется, демонстрационные данные добавляются.
  5) Открывает браузер на адресе сайта (через 3 секунды, чтобы сервер
     успел запуститься).
  6) Запускает app.py - начинается работа сайта. Остановка - Ctrl+C.

ПОЧЕМУ ЭТО УДОБНО
  Пользователю не нужно ничего помнить и вводить вручную: ни команд
  установки, ни паролей, ни путей. Один щелчок - и сайт открыт.
  Повторные запуски проходят быстрее: библиотеки и база уже на месте.

--------------------------------------------------------------------------------
3.2  app.py - ВСЕ СТРАНИЦЫ САЙТА
--------------------------------------------------------------------------------
НАЗНАЧЕНИЕ
  Главный файл. В нём описаны все страницы сайта и все запросы к базе.
  Запускается командой:  python app.py

НАЧАЛО ФАЙЛА
  Создаётся приложение Flask, задаётся секретный ключ (нужен для работы
  сессии - чтобы сайт помнил, кто вошёл) и предельный размер загружаемого
  файла - 8 МБ.

ВСПОМОГАТЕЛЬНЫЕ ФУНКЦИИ
  current_user()
      Смотрит в сессию номер пользователя и достаёт его из таблицы users.
      Если никто не вошёл - возвращает None.
  all_categories()
      Возвращает список категорий для выпадающего списка.
  add_user()  (context_processor)
      Делает переменную user доступной во всех шаблонах, чтобы в каждом
      из них не передавать её вручную. В шапке сайта по этой переменной
      решается, показывать ссылки «Войти/Регистрация» или «Выйти».
  page_not_found()  (errorhandler 404)
      Показывает простую страницу «Страница не найдена».

СТРАНИЦЫ

  @app.route("/")  - index()
      Главная страница: таблица всех объявлений.
      Можно передать два параметра в адресе:
          ?q=диван       - поиск по названию (без учёта регистра букв)
          ?category=3    - показать только выбранную категорию
      Запрос собирается по частям: сначала основная часть с JOIN
      (объявление + категория + продавец), потом при необходимости
      добавляется WHERE, в конце ORDER BY a.id DESC - свежие сверху.
      Значения подставляются через знак «?», а сами значения передаются
      отдельным списком - это защита от SQL-инъекций.

  @app.route("/ad/<int:ad_id>")  - ad_view()
      Страница одного объявления. Показывает фотографию, цену, город,
      категорию, продавца и описание. Дополнительно проверяет, добавлено
      ли объявление в избранное у текущего пользователя, чтобы показать
      правильную ссылку. Если объявления с таким номером нет - страница
      «Объявление не найдено».

  @app.route("/add", методы GET и POST)  - ad_add()
      Добавление объявления. Сначала проверяет, вошёл ли пользователь.
      При отправке формы:
        * читает поля title, description, price, city, category_id;
        * цена преобразуется в число (запятая заменяется на точку);
        * загруженный файл сохраняется в static/uploads под случайным
          именем (uuid), расширение проверяется по списку разрешённых;
        * если обязательные поля пустые - показывается сообщение
          «Заполните все обязательные поля»;
        * иначе выполняется INSERT и происходит возврат на главную.

  @app.route("/edit/<int:ad_id>", методы GET и POST)  - ad_edit()
      Редактирование. Проверяет, что объявление принадлежит текущему
      пользователю (иначе - «Это не ваше объявление»). При сохранении
      выполняется UPDATE. Если загружено новое фото - оно заменяет старое.

  @app.route("/delete/<int:ad_id>")  - ad_delete()
      Удаление своего объявления. Ссылка на удаление есть только на
      странице объявления и только у владельца.

  @app.route("/favorites")  - favorites()
      Список избранных объявлений пользователя (JOIN таблиц favorites
      и ads).

  @app.route("/favorite/<int:ad_id>")  - favorite()
      Добавляет объявление в избранное или убирает его оттуда.
      Сначала проверяет, есть ли уже такая запись: если есть - DELETE,
      если нет - INSERT.

  @app.route("/messages")  - messages()
      Список пользователей, с которыми уже есть переписка. Запрос ищет
      всех, кто отправлял сообщения текущему пользователю или получал
      их от него (через UNION двух подзапросов).

  @app.route("/messages/<int:user_id>", методы GET и POST)  - dialog()
      Переписка с конкретным пользователем: таблица сообщений
      (кто, текст, дата) и форма отправки нового сообщения.
      Нельзя открыть переписку с самим собой.

  @app.route("/register", методы GET и POST)  - register()
      Регистрация. Проверки: логин не короче 3 символов, пароль не
      короче 5, пароли совпадают, такой логин ещё не занят.
      Пароль сохраняется не как есть, а в виде хеша
      (generate_password_hash), поэтому прочитать его из базы нельзя.

  @app.route("/login", методы GET и POST)  - login()
      Вход. Ищет пользователя по логину и проверяет пароль по хешу
      (check_password_hash). При успехе номер пользователя записывается
      в сессию.

  @app.route("/logout")  - logout()
      Очищает сессию и возвращает на главную.

ЗАПУСК
  В конце файла (блок if __name__ == "__main__") сайт проверяет связь
  с базой и запускает веб-сервер на адресе из config.py. Если базы нет -
  печатает понятное сообщение и не запускается.

--------------------------------------------------------------------------------
3.3  config.py - НАСТРОЙКИ
--------------------------------------------------------------------------------
  Все параметры собраны в одном файле, чтобы не искать их по всему проекту.

  DB_HOST      - адрес сервера базы данных (localhost)
  DB_PATH      - путь к файлу базы. Определяется автоматически:
                   Windows : D:\AVITO_DB\AVITO.DB
                             (если диска D нет - C:\AVITO_DB\AVITO.DB)
                   Linux   : /var/lib/firebird/data/avito.fdb
                 Свой путь можно задать переменной окружения AVITO_DB_PATH.
  DB_USER      - пользователь базы (sysdba)
  DB_PASSWORD  - его пароль (masterkey)
  DB_CHARSET   - кодировка UTF8, чтобы правильно хранились русские буквы
  DB_POOL_SIZE - сколько соединений с базой держать открытыми

  SECRET_KEY   - ключ для подписи cookie-сессии
  WEB_HOST     - адрес сайта (127.0.0.1)
  WEB_PORT     - порт сайта (5000)
  DEBUG        - режим отладки

  BASE_DIR, STATIC_DIR, UPLOAD_DIR - пути к папкам проекта
  MAX_CONTENT_LENGTH - самый большой размер фотографии (8 МБ)
  ALLOWED_EXTENSIONS - разрешённые расширения файлов

  make_upload_dir()  - создаёт папку для фотографий, если её нет.
  firebird_help()    - возвращает подсказку, что делать, если сервер
                       Firebird не запущен. Подсказка своя для Windows
                       и своя для Linux, в ней готовые команды.

  В конце файла вывод в консоль переключается на UTF-8, чтобы русские
  сообщения скриптов были читаемыми и в Windows, и в Linux.

--------------------------------------------------------------------------------
3.4  db.py - РАБОТА С БАЗОЙ ДАННЫХ
--------------------------------------------------------------------------------
НАЗНАЧЕНИЕ
  Единственный файл, который напрямую общается с Firebird. Остальной код
  не знает, как устроен драйвер, - он просто вызывает готовые функции.

ЧТО ВНУТРИ
  DatabaseError
      Своё исключение, в которое заворачиваются все ошибки базы.

  _open_connection()
      Открывает соединение с базой через fdb.connect.

  _pool, _acquire(), _release()
      Пул соединений. Открывать соединение заново на каждый запрос долго,
      поэтому готовые соединения хранятся в очереди и переиспользуются.
      Перед выдачей соединение проверяется запросом "select 1 from
      rdb$database": если сервер перезапускался, соединение заменится
      на новое.

  _rows_to_dicts(cursor, rows)
      Firebird возвращает строки кортежами, а имена столбцов - заглавными
      буквами. Функция превращает их в словари с маленькими буквами:
      ('Ноутбук', 62000) -> {'title': 'Ноутбук', 'price': 62000}

  _run(sql, params, only_one)
      Основная работа: взять соединение, выполнить запрос, прочитать
      строки, сделать commit, вернуть соединение в пул. При ошибке
      делается rollback, а сообщение переводится на русский язык
      (например, «Запись с таким значением уже существует»).

  Публичные функции, которыми пользуется app.py и seed.py:
      query_all(sql, params)            - список словарей (SELECT)
      query_one(sql, params)            - одна строка или None
      query_value(sql, params, default) - одно значение (например COUNT)
      execute(sql, params, returning)   - INSERT/UPDATE/DELETE;
                                          при returning=True возвращает
                                          новый номер записи
      ddl(statement)                    - выполнить команду CREATE (для schema.py)
      ping(retries, delay)              - проверить связь с базой

ВАЖНО
  Все запросы выполняются с заглушками «?», а значения передаются
  отдельным списком. Поэтому то, что пользователь введёт в форму, никогда
  не станет частью команды SQL.

--------------------------------------------------------------------------------
3.5  schema.py - СТРУКТУРА БАЗЫ ДАННЫХ
--------------------------------------------------------------------------------
НАЗНАЧЕНИЕ
  Приводит базу данных к нужному виду. Скрипт можно запускать много раз -
  он сначала проверяет, есть ли уже такой объект, и только потом создаёт.

ЧТО СОЗДАЁТ
  1) недостающие столбцы в таблицах;
  2) последовательности (sequence) для автоматической нумерации записей;
  3) триггеры, которые заполняют поле id при вставке;
  4) индексы - чтобы поиск по базе работал быстрее;
  5) ограничения CHECK - правила проверки данных на стороне базы;
  6) представления (VIEW) - сохранённые сложные запросы с именем;
  7) хранимые процедуры.
  Всё это описано списками COLUMNS, SEQUENCES, AUTO_ID_TRIGGERS, INDEXES,
  CHECKS, VIEWS, PROCEDURES - чтобы добавить новый объект, достаточно
  дописать одну строку в список.

КАК УСТРОЕН
  В начале идут функции-проверки, которые читают системные таблицы
  Firebird (rdb$relations, rdb$relation_fields, rdb$triggers и другие):
      table_exists(), column_exists(), sequence_exists(),
      trigger_exists(), index_exists(), constraint_exists()

  Функция upgrade() проходит по спискам и выполняет нужные команды
  ALTER TABLE, CREATE INDEX, RECREATE VIEW и так далее.

  describe_type() и table_columns() собирают читаемое описание столбцов
  (VARCHAR(255), NUMERIC(12,2), TIMESTAMP) - для справки.

  schema_report() возвращает списки таблиц, представлений, процедур
  и триггеров.

ВАЖНО ПОНИМАТЬ
  Сайт из app.py пользуется ТОЛЬКО пятью основными таблицами и их
  исходными столбцами. Представления, процедуры и дополнительные столбцы
  (статус объявления, счётчик просмотров, дата создания и другие) в этом
  варианте сайта не используются - они остались в базе как отдельная,
  «серверная» часть курсовой работы.

ТОНКОСТЬ FIREBIRD
  Условие в триггере записывается так:
      IF (условие) THEN
      BEGIN
          ...
      END
  Если написать IF ... THEN команда; END, то Firebird считает этот END
  закрывающей скобкой внешнего блока BEGIN и триггер получится
  незакрытым. Поэтому везде используется конструкция с BEGIN ... END.

--------------------------------------------------------------------------------
3.6  setup_all.py - СОЗДАНИЕ БАЗЫ ДАННЫХ
--------------------------------------------------------------------------------
НАЗНАЧЕНИЕ
  Создаёт файл базы данных с нуля и применяет структуру.

Ключи запуска:
    python setup_all.py           создать базу, если её нет, и обновить структуру
    python setup_all.py --demo    то же самое плюс демонстрационные данные
    python setup_all.py --reset   удалить базу и создать заново (спросит
                                  подтверждение)

ЧТО ДЕЛАЕТ
  database_exists()  - проверяет, отвечает ли база по указанному пути;
  remove_database()  - удаляет файл базы (только при ключе --reset);
  create_database()  - создаёт базу в кодировке UTF8 и пять таблиц:
                       users, categories, ads, favorites, messages;
  schema.upgrade()   - добавляет последовательности, триггеры, индексы,
                       ограничения, представления и процедуры;
  seed.main()        - при ключе --demo заполняет базу данными.

  Файл BASE_TABLES в начале скрипта содержит команды CREATE TABLE для
  всех пяти таблиц - это и есть структура базы в её первоначальном виде.

8. БАЗА ДАННЫХ: ТАБЛИЦЫ И СВЯЗИ
================================================================================

  users (пользователи)
      id             - номер записи (первичный ключ)
      login          - логин, только один такой
      password_hash  - хеш пароля
      role           - роль: user или admin

  categories (категории объявлений)
      id, name (уникальное название), description

  ads (объявления)
      id, user_id (кто подал), category_id (какая категория),
      title (название), description (описание), price (цена),
      city (город), image_url (путь к фотографии)

  favorites (избранное)
      id, user_id, ad_id
      Одна и та же пара (пользователь, объявление) может встречаться
      только один раз.

  messages (сообщения)
      id, sender_id (кто отправил), receiver_id (кому),
      ad_id (по какому объявлению), message_text (текст),
      created_at (дата и время)

СВЯЗИ
      users 1 ------< ads >------ 1 categories
      users 1 ------< favorites >------ 1 ads
      users 1 ------< messages >------ 1 ads

  Внешние ключи объявлены с правилом ON DELETE CASCADE: если удалить
  пользователя, автоматически удалятся и его объявления, и его записи
  в избранном, и его сообщения.

  Пароли в базе хранятся только в виде хеша PBKDF2-SHA256. Это значит,
  что по содержимому таблицы users нельзя узнать настоящий пароль -
  можно только проверить, правильно ли он введён.

9. КАК РАБОТАЮТ ОСНОВНЫЕ СЦЕНАРИИ
================================================================================

СЦЕНАРИЙ 1. ГОСТЬ ОТКРЫВАЕТ ГЛАВНУЮ СТРАНИЦУ
  Браузер запрашивает адрес «/».
  Flask вызывает функцию index() из app.py.
  Функция собирает SQL-запрос с JOIN трёх таблиц (ads, categories, users)
  и вызывает db.query_all().
  db.py берёт соединение из пула, выполняет запрос и превращает строки
  в словари.
  Шаблон index.html выводит данные таблицей с рамкой.

СЦЕНАРИЙ 2. ПОИСК ОБЪЯВЛЕНИЯ
  Пользователь вводит слово и нажимает «Найти».
  Браузер отправляет адрес «/?q=диван».
  Функция index() добавляет к запросу условие
      upper(a.title) like upper(?)
  с параметром «%диван%». Функция upper нужна, чтобы поиск не зависел
  от регистра букв.

СЦЕНАРИЙ 3. РЕГИСТРАЦИЯ И ВХОД
  Пользователь заполняет форму на странице /register.
  Функция register() проверяет длину логина и пароля, совпадение паролей
  и то, что такой логин ещё не занят.
  Пароль превращается в хеш функцией generate_password_hash и попадает
  в таблицу users.
  Затем на странице /login функция login() ищет пользователя по логину
  и проверяет пароль функцией check_password_hash.
  Если всё верно, номер пользователя записывается в сессию, и сайт
  «запоминает» его до выхода.

СЦЕНАРИЙ 4. ДОБАВЛЕНИЕ ОБЪЯВЛЕНИЯ
  Пользователь открывает /add и заполняет форму.
  Функция ad_add() читает поля, преобразует цену в число и сохраняет
  загруженную фотографию в папку static/uploads под случайным именем.
  Затем выполняется команда INSERT, и сайт возвращается на главную
  страницу с сообщением «Объявление добавлено».

СЦЕНАРИЙ 5. ИЗБРАННОЕ
  На странице объявления есть ссылка «Добавить в избранное».
  Функция favorite() проверяет, есть ли уже такая запись:
    - если запись есть, выполняется DELETE (убрать из избранного);
    - если записи нет, выполняется INSERT (добавить в избранное).
  Список избранного показывается на странице /favorites.

СЦЕНАРИЙ 6. ПЕРЕПИСКА
  На странице объявления есть ссылка «Написать продавцу».
  Открывается страница /messages/<номер продавца> с таблицей сообщений
  и формой отправки.
  При отправке выполняется INSERT в таблицу messages, и страница
  открывается заново - уже с новым сообщением.
  Список всех переписок находится на странице /messages.

11. ЧАСТЫЕ ВОПРОСЫ
================================================================================

ВОПРОС: почему сайт выглядит так просто?
ОТВЕТ: так и задумано. Оформление сделано нарочно простым: только чёрный
  и белый цвет, обычные теги HTML и таблицы с рамкой. Никаких внешних
  библиотек оформления не подключается.

ВОПРОС: почему нет панели администратора, статистики и счётчика просмотров?
ОТВЕТ: сайт использует только те данные, которые есть в пяти исходных
  таблицах. Всё, что требовало дополнительных столбцов (статус
  объявления, число просмотров, блокировка пользователя), из сайта
  убрано, чтобы не усложнять работу.

ВОПРОС: в базе есть представления, процедуры и дополнительные столбцы,
         а сайт их не использует. Это ошибка?
ОТВЕТ: нет. Это отдельная, «серверная» часть курсовой работы - она
  показывает возможности самой СУБД. Сайт же намеренно оставлен простым.

ВОПРОС: при запуске написано «Нет связи с базой данных».
ОТВЕТ: не запущена служба сервера баз данных.
  Windows: откройте «Службы» (services.msc), найдите RedDatabase Server -
  DefaultInstance и нажмите «Запустить».
  Linux: выполните  sudo systemctl start firebird
  Скрипт start.py сам проверяет это и печатает нужную команду.

ВОПРОС: как запустить проект на другом компьютере?
ОТВЕТ: скопировать папку с проектом и запустить start.bat (Windows)
  или ./start.sh (Linux). Скрипт сам определит, где должна лежать база
  данных, поставит библиотеки и всё подготовит. Единственное, что нужно
  иметь на компьютере, - установленный сервер Firebird.

ВОПРОС: почему в start.bat нет русских слов?
ОТВЕТ: командная строка Windows неправильно читает русский текст внутри
  bat-файла и ломает его. Поэтому в start.bat только команды латиницей,
  а все сообщения выводит start.py - там с кодировкой всё в порядке.

ВОПРОС: как полностью пересоздать базу вместе с данными?
ОТВЕТ: python setup_all.py --reset --demo

ВОПРОС: как очистить базу от демонстрационных данных?
ОТВЕТ: python setup_all.py --reset   (создаст пустую базу)

ВОПРОС: сайт не запускается, пишет, что порт занят.
ОТВЕТ: измените WEB_PORT в файле config.py, например на 8080,
  и запустите снова.

ВОПРОС: где хранятся фотографии объявлений?
ОТВЕТ: в папке static/uploads. При загрузке файлу даётся случайное имя,
  чтобы два разных пользователя не перезаписали фотографии друг друга.

ВОПРОС: почему в таблице users лежат непонятные строки вместо паролей?
ОТВЕТ: это хеши. Пароль невозможно восстановить из хеша - можно только
  проверить, правильно ли он введён. Так и должно быть.
